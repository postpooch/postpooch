# Google Business architecture

PostPooch treats a Zernio/Google connection and a Google Business Profile location as separate records. A connection can own many locations, while one location is selected for the current editor experience. All application code calls `GoogleBusinessService`; only `zernio-provider.ts` knows the Zernio SDK.

Dashboard reads come from PostgreSQL/Supabase. Accepted edits are sent to Zernio first and persisted only after the provider confirms success. Every accepted edit increments `mutation_version`; a reconciliation snapshot only updates profile fields when its captured version is still current.

`start-daily-google-business-sync` begins at 4:00 AM in `America/Phoenix`. The project had no existing application-wide daily timezone convention, so Phoenix matches the PostPooch operating timezone. The coordinator batch-enqueues independent location workers. Workers share a concurrency limit of four, default to 40 requests/minute, reserve at least 25% of Zernio's reported capacity, honor `Retry-After`, and use Trigger.dev durable waits between calls. Set `GOOGLE_BUSINESS_SYNC_REQUESTS_PER_MINUTE` to tune the conservative default without changing code.

Zernio `review.new` and `review.updated` events keep reviews fresh between reconciliations. The webhook route verifies the raw-body HMAC using `ZERNIO_WEBHOOK_SECRET` and deduplicates the stable event ID in PostgreSQL.

The editor can update Knowledge Panel fields that Zernio exposes: name, address, description, website, phones, regular hours, special hours, open status, service-area type, services, boolean attributes, place-action links, and photos. Category, verification, ratings, and review counts stay read-only. New photos are uploaded to Cloudflare R2 first so Zernio can fetch a public `sourceUrl`; add and delete then follow the same Zernio-first, Postgres-second pipeline as other fields. Google does not expose an in-place photo patch, so category changes delete and recreate the media item. Nightly sync lists media and prunes `images` rows that Google no longer returns, but only when the location `mutation_version` still matches.
